= Containers
:description: How to use containers in WebLibre to organize tabs and optionally isolate cookies and site data.

Containers help you separate different kinds of browsing inside WebLibre.
You can use them to keep work sites away from personal sites, send one container through Tor or a proxy, or make certain sites always open in the same place.

Important: containers do not isolate cookies by default.
A new container starts as an organization and routing tool.
It only gets its own cookie and site-data context when you turn on *Cookie Isolation*.

== Why Containers Matter

Many websites and trackers try to connect your activity across different sites.
If you use the same browser identity everywhere, it is easier for them to link your shopping, social media, work tools, and other browsing together.

Containers help you split that activity into separate spaces.
That can mean simple tab organization, or full site-data separation if you enable *Cookie Isolation* for the container.

For example, you might use:

* *Personal* for social media and news
* *Work* for company tools and work email
* *Shopping* for stores and price comparisons
* *Banking* for financial sites

That makes it easier to stay organized, and when you turn on *Cookie Isolation*, it also separates cookies and site data between containers.

== What Containers Do

Some container features always work:

* *Name*, color, and icon
* *Assigned Sites*
* *Pin Container* and manual reordering
* *Exclude from Search Index*
* selecting the container for new tabs
* grouping tabs under that container in the UI
* container-colored address bar border and tab bar tint when browsing in that container

Other features only work when *Cookie Isolation* is enabled for that container:

* *Cookie Isolation*
* *Proxy Connection* (route the container through Tor or a proxy profile)
* *Bypass Global Proxy*
* *Clear Data on Exit*
* *Exclude from History*
* *Strict Mode*
* separate cookies, saved logins, and site data
* *Clear Container Data*

Important: a container only keeps separate logins, cookies, and site data when *Cookie Isolation* is enabled for that container.
A non-isolated container is still useful for organization and site assignment, but it does not get its own cookie jar.

With *Cookie Isolation* turned on, websites in one container cannot use the cookies or site data from another container.
For example, if you sign in to a site in your *Work* container, that sign-in does not automatically carry over to your *Personal* container.

== Container Colors and Icons

When you browse in a container, the address bar shows a subtle colored border matching the container's theme color, and the tab bar area is tinted with the same color.
This makes it easy to recognize which container you are in without checking the container menu.

Each container can also have its own icon.
The icon appears in the container bar, the container list, and tab indicators.
You pick it from a searchable grid of Material Design Icons in the container editor.

Container colors come in two modes:

* standard seeded colors from the built-in palette
* custom colors with direct hex and HSL controls, for exact color matching

To change either, open the container editor and tap the large icon and color preview, then choose *Change Color* or *Change Icon*.

== A Practical Example

Suppose you create these containers:

* *Personal* -- social media, news, entertainment
* *Work* -- company tools and work email
* *Shopping* -- online stores
* *Banking* -- your bank and payment sites

Then you can:

* keep work logins in *Work*
* keep store tracking in *Shopping*
* reserve *Banking* for sensitive sites
* optionally send only one container through Tor or a proxy

This does not make you invisible, but it can reduce how much different sites learn from each other.

== Create and Manage Containers

One reliable way to manage containers is:

. Open the browser menu
. Go to *Containers*
. Tap *Manage Containers*
. Tap *Container* to create a new one

When creating a container, you can set:

* *Container Name* -- a label such as `Work` or `Shopping`
* color and icon -- tap the large preview to open *Change Color* and *Change Icon*
* *Pin Container* -- keeps this container at the top of lists
* *Cookie Isolation* -- gives the container its own cookies and site data
* *Proxy Connection* -- routes this container through Tor or a proxy profile
* *Clear Data on Exit* -- clears cookies and site data when the app closes
* *Exclude from Search Index* -- skips pages in this container from the local search index
* *Exclude from History* -- keeps pages in this container out of browsing history
* *Strict Mode* -- only allows assigned sites to load in this container
* *Assigned Sites* -- automatically sends chosen sites to this container

When editing an existing container, always expect name, appearance, pinning, and assigned-site management to be available.
Proxy routing, per-container data clearing, history exclusion, and strict mode only make sense for containers that already have *Cookie Isolation*.

Note: *Proxy Connection*, *Clear Data on Exit*, *Exclude from History*, and *Strict Mode* depend on *Cookie Isolation*. If cookie isolation is off, those options are not active for that container because there is no separate browsing context to route, clear, or restrict.

== Use a Container for Tabs

You can use containers in two main ways:

* Select a container first, then open new tabs inside it.
* Assign an already open tab to a container.

To select a container for new tabs:

. Open the browser menu
. Go to *Containers*
. Tap *Manage Containers*
. On the container you want, use *Select*

To move an existing tab into a container:

. Open the browser menu for that tab
. Go to *Containers*
. Tap *Assign Container*
. Choose the container

If needed, you can also remove a tab from a container with *Unassign Container*.

If moving a tab changes its cookie-isolation context, WebLibre may reopen that tab in the new context so it uses the right cookies and site data.

== Site Assignments

*Assigned Sites* let you tell WebLibre that a site should always use a specific container.
This is useful for sites you visit often and always want to keep separated.

Examples:

* `github.com` -> *Work*
* `facebook.com` -> *Personal*
* `amazon.com` -> *Shopping*

When possible, WebLibre will open or move that site into the assigned container automatically.

To set this up:

. Open *Manage Containers*
. Open the container you want to edit
. Tap *Assigned Sites*
. Add the site, such as `example.com`

Helpful notes:

* WebLibre stores the site as a site origin, such as `https://example.com`.
* A site can only be assigned to one container at a time.
* If a site is already assigned somewhere else, WebLibre warns you.
* Site assignment works even when *Cookie Isolation* is off. In that case the site still opens in that container, but it does not get separate cookies or site data.

=== Wildcard Assignments

Site rules support wildcards so you can match a domain and all of its subdomains in one rule.

* Enter `*.example.com` to match the apex domain *and* every subdomain (`example.com`, `mail.example.com`, `app.example.com`, ...)
* Exact-origin entries still win over wildcard matches when both apply, so you can fine-tune routing for specific subdomains

For example, if you have `mail.example.com` assigned to *Work* and `*.example.com` assigned to *Personal*, links to `mail.example.com` open in *Work* and all other `example.com` subdomains open in *Personal*.

This is convenient for services that span many subdomains, such as cloud providers or company tools.

== Unsaved Changes Warning

If you edit a container and press the back button without saving, WebLibre asks what you want to do:

* *Save* the changes
* *Discard* the changes
* *Keep editing* and stay on the screen

This avoids accidentally losing changes when you navigate away by reflex.

== Pin and Reorder Containers

Turn on *Pin Container* to keep a container at the top of container lists.
Pinned containers show a pin icon on the container chip and a *Pinned* badge in the container list.

You can also reorder containers manually: long-press and drag container chips in the bottom container bar, or use the drag handles in the container list.
The order persists across sessions.

== Per-Container Proxy Routing

If you set a *Proxy Connection* for a cookie-isolated container, tabs in that container route their traffic through that connection -- Tor or any of your proxy profiles -- while other containers keep using your normal connection.

Example:

* *Personal* uses your regular connection
* *Sensitive* uses *Cookie Isolation* plus Tor as its *Proxy Connection*
* *Remote* uses *Cookie Isolation* plus a WireGuard proxy profile

This lets you mix regular, Tor-routed, and proxy-routed browsing in the same browser.

If global proxy routing is enabled instead, a container can opt out with *Bypass Global Proxy*.
That container then connects directly -- useful for sites that block Tor or proxy traffic.
A container cannot bypass the global proxy and have its own proxy assignment at the same time.

Learn more: xref:tor.adoc[Tor Integration] and xref:proxy.adoc[Proxy Connections]

== Strict Mode

*Strict Mode* turns a container into an allowlist-only space.

When enabled, only sites assigned to that container are allowed to load there.
Unassigned sites are blocked instead of loading inside the strict container.
Sites assigned to another container are still redirected or handled according to their assignment.

This is useful for containers that should stay clean, such as a *Banking* container that should only ever open your bank's sites.

*Strict Mode* requires *Cookie Isolation*.

== Exclude from History

With *Exclude from History* enabled, pages opened in that container are not recorded in browsing history.

This is separate from *Exclude from Search Index*: it prevents the container's visits from being recorded in browser history at all, not just from the local search index.

*Exclude from History* requires *Cookie Isolation*.

== Exclude from Search Index

WebLibre can index the pages you visit locally so you can search their content later (see xref:search/local-search.adoc[Local Search]).

Turn on *Exclude from Search Index* to keep a container's pages out of that index.
Existing indexed entries that only come from that container are removed immediately.
If you disable the option again, eligible pages that are still open can be indexed again.

This option does not require cookie isolation.

== Clear Data on Exit

If you enable *Clear Data on Exit* for a cookie-isolated container, WebLibre clears that container's cookies and site data when the app closes.

This is useful for:

* temporary accounts
* short research sessions
* containers where you do not want sign-ins to persist

It is a good choice when you want a container to start fresh the next time you use it.

== Delete a Container

When you delete a container, WebLibre can also offer to delete that container's browsing history.
If you keep the history, those visits stay in the History screen but are shown without a container label.

== Things to Expect

* Containers help with separation, but a plain container is not the same as an isolated browsing context.
* Turn on *Cookie Isolation* for any container where separate logins or cookies matter.
* If you need one-off isolation without creating a container first, use xref:tabs/tab-management.adoc[isolated tabs].
* You can combine containers with private tabs.
* Colors and icons help you recognize containers on the address bar, in container lists, and in related tab UI.
* The address bar border and tab bar tint change to match your active container.
* New visits record which container they came from, so you can filter xref:history-downloads.adoc[History] by container.

== Tips

* Start with two or three containers, such as *Personal*, *Work*, and *Shopping*.
* Turn on *Cookie Isolation* for any container where separate logins matter.
* Use *Assigned Sites* for sites you open repeatedly.
* Use wildcard patterns in assigned sites to cover multiple related domains.
* Use *Strict Mode* for containers that should only ever load their assigned sites.
* Use *Clear Data on Exit* for temporary or sensitive browsing.
* Use *Assign Container* when a tab was opened in the wrong place.
* Pin the containers you use most so they stay at the top of lists.
* Watch the address bar color to confirm you are in the right container.
